# Coverage — what is documented, built and published

Generated from the repository on **2026-08-10**. Every figure below was read off
the tree and the built site, not estimated.

Three things have to line up for a component to be genuinely usable:

| Layer | Where it lives |
|---|---|
| **Documented** | `components/<name>/` — `spec.md` (the contract) and/or `guidelines.md` (the usage page) |
| **Built** | `packages/web/src/` and `packages/react/src/` |
| **Published** | a page on the DS website |

A gap in any one of them is worth knowing about. None of the gaps below are
defects in what exists — they are things that exist in one layer and not yet in
another.

## Where everything lives

For anyone who wants to open the actual files rather than take this on trust.

### Tokens

| What | Path | Edit it? |
|---|---|---|
| **Source of truth** | `foundations/tokens/**/*.json` | **Yes** — this is the only place a token value is authored |
| Primitives | `foundations/tokens/primitives/` (colour, typography) | Yes |
| Semantics | `foundations/tokens/semantic/` | Yes |
| Built CSS custom properties | `packages/tokens/build/css/tokens.css`, `tokens-dark.css` | No — generated |
| Built XAML (MAUI) | `packages/tokens/build/xaml/Tokens.xaml`, `Tokens.Dark.xaml` | No — generated |
| Flat JSON (for tooling) | `packages/tokens/build/json/tokens-flat.json` | No — generated |
| Human-readable colour reference | `foundations/tokens/colour/global.md`, `semantic.md` | **No** — generated by `scripts/sync-token-docs.mjs` |

Regenerate everything downstream of a token change with `npm run build:tokens`.
The build fails rather than drifting if the committed output disagrees.

### Component code, per framework

| Framework | Path | Shape |
|---|---|---|
| Web (HTML/CSS) | `packages/web/src/<component>/<component>.css` | The reference implementation every other target leans on |
| React | `packages/react/src/<component>/<Component>.jsx` | Plus a `.stories.jsx` beside it |
| Blazor | `packages/blazor/src/<Component>/` | Razor class library, `DHCW.SingleRecord.Components.csproj` |
| .NET MAUI | `packages/maui/` | `Colors.xaml`, `Styles.xaml`, `Icons.xaml` — a token and style layer, not a component library (DDR-021) |
| Icons | `foundations/iconography/svg/<group>/<name>.svg` | Source SVGs; `packages/icons/build/` holds the generated sprite and JS |

### Built output a consumer downloads

`packages/web/dist/` — `single-record.css` (everything, flattened),
`single-record-dark.css`, `icons.js`, `sprite.svg`, and
`components/<name>.css` for one component at a time. Committed deliberately, so
the files can be taken straight from GitHub without a build. Documented on the
site's **Get the files** page.

### The website and its code snippets

**Every code snippet on the DS website is authored in one file:
`packages/website/build.mjs`.** They are not separate snippet files. Search that
file for the panel id (`'type-links'`, `'table'`, `'breadcrumbs-back'`) to find
the four framework tabs for a given block.

Two build-time checks stop a snippet from lying, and both fail the build:

- **React snippets** are checked against each component's own destructured
  props. It cannot tell you a *value* is wrong, only that a prop does not
  exist — which is the failure that actually happens.
- **MAUI snippets** are checked against the resources `@dhcw/sr-maui` really
  ships (`Colors.xaml` + `Styles.xaml` + `Icons.xaml`), and reject literal
  colours.

`packages/website/site.css` is the website's own styling — not part of the
design system, and it must never restyle a component inside a preview.

## D. Documented, but not built

`document-viewer`, `icons`, `link`, `progress-indicators`, `search`, `toggles`.

Three of these are expected rather than gaps:

- **`document-viewer`** is a specification for a wrapper a licensed developer
  implements — see `components/document-viewer/spec.md`.
- **`icons`** is a foundation, published under Styles, and ships as
  `@dhcw/sr-icons` rather than a component folder.
- **`toggles`** documents `switch` and `segmented-control`, both of which *are*
  built; the folder name simply does not match the code folder names.

That leaves **`link`, `progress-indicators` and `search`** as genuinely
specified-but-unbuilt.

## Spec and guidelines coverage

A `spec.md` is the contract; a `guidelines.md` is the usage page and the source
for both the website page and the Figma usage panel. Most folders have one but
not the other.

| Has both | Spec only | Guidelines only |
|---|---|---|
| `document-viewer`, `patient-banner`, `table` | `autocomplete`, `button`, `checkbox`, `link`, `modal`, `progress-indicators`, `search`, `select`, `tags` | `breadcrumbs`, `footer`, `header`, `icons`, `input`, `navigation`, `toggles` |

**The "guidelines only" column is the one that matters for published pages** —
those seven all have live website pages built from their guidelines, so the
missing `spec.md` is an internal contract gap rather than something a reader
hits. **`button` is the notable one in the other column**: it has a spec and a
published page, but no `guidelines.md`.

## What is verified automatically

These run in `npm run check` and `npm run build:site`, and fail the build rather
than reporting:

| Check | Covers |
|---|---|
| `check-typography.mjs` | no raw type declarations outside the scale (baseline 0) |
| `check-design-system.mjs` | conformance findings held at a baseline of 16 |
| React snippet check | a snippet cannot use a prop the component does not have |
| MAUI snippet check | every `{StaticResource …}` exists in `@dhcw/sr-maui`; no literal colours |
| `verify-icons.mjs` | all 120 MAUI icon geometries match their source SVGs |
| `verify-xaml.mjs` | XAML/csproj well-formed, resources resolve, no literal colours |
| Prototype component check | a prototype cannot use a component its embed does not ship |
| Web dist check | the site build fails if `packages/web/dist` is missing |

## Suggested order of work

1. **Publish `modal` and `tags`.** Code exists, specs exist, no page. Lowest
   effort, highest visible gain.
2. **Document `status-indicator`.** Built and in use, with nothing written down.
3. **Write `button/guidelines.md`.** The most-used component in the system has a
   published page and no usage guidance behind it.
4. **Decide on `link`, `progress-indicators` and `search`** — specified but
   unbuilt. Either build them or mark the specs as deferred, so the gap is a
   decision rather than a silence.
