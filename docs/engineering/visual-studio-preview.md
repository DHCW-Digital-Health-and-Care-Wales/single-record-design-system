# Previewing SR Components in Visual Studio — Blazor + MAUI

How to preview the design system's Blazor components in a **web** host *and* in a
**native MAUI** shell, from **one shared component source**, in Visual Studio.

The Blazor **component library already exists in this repo** (`packages/blazor`).
You clone the repo, add one or two small **host apps** with the VS templates,
reference the library, and press **F5**.

> **Why you add the hosts (not me):** the library is committed and standard. The
> host apps and the MAUI project are best generated by the VS templates so they
> match your installed workloads and .NET version exactly — that's more reliable
> than hand-written project files. The steps below take a few minutes.

---

## First: "Clone a repository" or "Create a new project"?

When you opened Visual Studio it asked this. The answer:

- **Clone a repository.** Paste your design-system repo URL
  (`https://github.com/Chuk-DCHW/dhcw-single-record-design-system`) and clone it
  locally. This pulls down the repo **including the Blazor component library**.
- **Do _not_ choose "Create a new project"** at that screen — that starts an
  empty project unrelated to your repo.
- If you've **already cloned** it, choose **Open a project or solution** (or
  *Open a local folder*) and point at your cloned repo folder.

After cloning, you'll create the host app(s) *inside* that cloned repo (Steps 2–3).

---

## The idea: one component source, many hosts

```
packages/blazor  →  Razor Class Library (RCL): SrButton + Gallery   ← EXISTS in repo
                         │  referenced by
        ┌────────────────┴───────────────────┐
   Blazor Web host                     MAUI Blazor Hybrid host
   (browser preview,                   (native Windows/Android shell,
    later → GitHub Pages)               hot reload, in Visual Studio)
        └──────── both render the SAME <Gallery /> + SAME CSS ────────┘
```

You write each component **once** (in the RCL). Each host is a thin shell that
renders the shared `<Gallery />`. The MAUI host is what gives you the "MAUI
preview" — the same Blazor components running natively.

> **On "Button for MAUI":** by design (DDR-011) there is **one** component source.
> The MAUI preview renders the *Blazor* Button natively via a Blazor Hybrid host —
> we do **not** maintain a separate native-XAML Button. A native-XAML control set
> would be a separate, deliberate decision (its own DDR) only if a component
> genuinely can't be web-rendered.

## Prerequisites (one-time)

1. **Visual Studio 2022** (17.8+).
2. **.NET 8 SDK** (LTS). Keep every project on the same TFM.
3. **VS workloads** — Installer → *Modify* → *Workloads*, tick:
   - **ASP.NET and web development** (Blazor web host)
   - **.NET Multi-platform App UI development** (MAUI Blazor Hybrid)
4. **Node** — run `npm install && npm run build:tokens` at the repo root so the
   token CSS exists (the copies in `packages/blazor/wwwroot/css` were generated
   this way; refresh them after token changes — see the note in the `.csproj`).

---

## Step 1 — open the library

After cloning, in VS: **File → Open → Project/Solution →**
`packages/blazor/DHCW.SingleRecord.Components.csproj` (or open the repo folder).
It should restore and build on its own (it's a class library — it can't run by
itself; that's what the hosts are for). If it builds, the components are good.

---

## Step 2 — Blazor Web host (browser preview → later, Pages)

1. **File → Add → New Project → Blazor Web App** → name it `BlazorGallery`, put it
   under a new `preview/` folder in the repo. (Interactive render mode "Server"
   is fine; the gallery is presentational.)
2. **Add a project reference** to
   `packages/blazor/DHCW.SingleRecord.Components.csproj`
   (right-click BlazorGallery → *Add → Project Reference*).
3. In the host's root document (`Components/App.razor`), add the two CSS links in
   `<head>`, **before** the existing `…styles.css` link:
   ```html
   <link rel="stylesheet" href="_content/DHCW.SingleRecord.Components/css/tokens.css" />
   <link rel="stylesheet" href="_content/DHCW.SingleRecord.Components/css/button.css" />
   ```
4. Render the shared gallery on the home page — replace the body of
   `Components/Pages/Home.razor` with:
   ```razor
   @page "/"
   @using DHCW.SingleRecord.Components
   <Gallery />
   ```
5. Set **BlazorGallery** as the startup project → **F5**. The Button matrix opens
   in your browser, styled by SR tokens.

Later, this same host is your **Blazor WASM gallery**: publish it and upload to
GitHub Pages (e.g. a `/blazor/` subpath), consistent with the preview/publish
split in **DDR-014**.

---

## Step 3 — MAUI Blazor Hybrid host (native preview in VS)

1. **File → Add → New Project → .NET MAUI Blazor Hybrid App** → name it
   `MauiGallery`, also under `preview/`.
2. **Add a project reference** to the same RCL.
3. In `wwwroot/index.html` `<head>`, add the same two CSS links as Step 2.
4. Replace the sample content of `Components/Pages/Home.razor` with:
   ```razor
   @using DHCW.SingleRecord.Components
   <Gallery />
   ```
5. Set the debug target to **Windows Machine** (fastest) or an Android emulator →
   **F5**. A native window opens rendering the *same* SR components. **.NET Hot
   Reload** applies C#/Razor edits live.

When real native MAUI XAML controls arrive in `packages/maui`, add that library
to the solution and preview it with **XAML Hot Reload** / **Live Preview** in this
same VS instance.

---

## Step 4 — one solution (optional but convenient)

Once both hosts exist: **File → Save All**, then **File → New → Solution** (or let
VS create one when you add the second project) containing the RCL + both hosts,
saved as `preview/SingleRecord.Preview.sln`. Open that one solution and switch the
**startup project** to flip between web and native preview — your single
previewer. Commit the `preview/**` projects to your repo so it's clone-and-run
next time.

---

## Keeping preview in sync

Hosts consume the generated `tokens.css` + `button.css` copied into the RCL's
`wwwroot/css`. After a token or component change: `npm run build:tokens`, re-copy
(command is in the `.csproj` comment), rebuild the host. This mirrors the
**DDR-014** rule that *preview* tracks current work while the *published* website
tracks a release tag.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| MAUI project won't create/build | MAUI workload missing | VS Installer → Modify → tick *.NET MAUI development* |
| Buttons render unstyled | Token/component CSS not loaded | Confirm the two `_content/DHCW.SingleRecord.Components/css/…` links resolve (F12 → Network); ensure `wwwroot/css` has the files |
| `_content/...` 404 | Host missing the project reference | Add the reference to `DHCW.SingleRecord.Components.csproj` |
| Windows target greyed out | Not on Windows | Use an Android emulator target |
| CSS edits don't hot-reload | Static CSS isn't part of .NET Hot Reload | Re-run the host; use the **web** host for fast CSS iteration |
| Version conflicts | Mixed .NET versions | Put RCL + hosts on the **same** TFM (`net8.0` / `net8.0-*`) |

## Notes / follow-ups

- **No native MAUI XAML controls yet** — `packages/maui` is a placeholder; the
  MAUI preview is the Blazor Hybrid host until/unless native controls are built.
- **`packages/web` has no aggregated `index.css`** (its `main` points at a missing
  file). Until one exists, hosts link component CSS individually (here, just
  `button.css`). Worth adding an `index.css` that `@import`s each component.
- **This web session has no .NET SDK**, so the library and hosts are built/run in
  Visual Studio on your machine. If VS shows a build error on the committed
  library, send me the exact message and I'll fix it in the repo.
